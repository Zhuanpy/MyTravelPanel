# 数据库备份

脚本：`scripts/tools/db_backup.py`

**就地备份**：在服务器上跑就存服务器，在本机跑就存本机，两边互不相干，不做跨机传输。

## 它做了什么

- `mysqldump` 导出全库（表结构 + 数据 + 存储过程 + 触发器 + 事件），gzip 压缩
- 用 `--single-transaction` 取一致性快照，**不锁表**，线上可以随时跑
- 导出完先校验文件末尾有 `Dump completed` 才改成正式文件名。中途磁盘满或进程被杀，只会留下 `.part` 残件，不会留一个看着像成功、恢复时才发现是半截的文件
- 按份数轮转，默认每个库留最近 8 份（每周一次≈两个月）
- 密码通过临时 `--defaults-extra-file` 传给 mysqldump，**不走命令行参数**（命令行参数在 `ps` 里对同机所有用户可见）
- 不依赖 Flask 应用，应用挂了、代码改坏了照样能跑

存放位置默认 `<项目根>/backups/db/`。`backups/` 已在 `.gitignore` 里，**备份文件不会进 Git**（里面是全部客户数据，绝不能提交）。

## 手动跑一次

```bash
# 服务器
cd /var/www/MyTravelPanel && venv/bin/python scripts/tools/db_backup.py

# 本机 Windows
python scripts/tools/db_backup.py
```

参数：

| 参数 | 说明 |
|---|---|
| `--dir` | 备份存放目录，默认 `<项目根>/backups/db` |
| `--keep` | 每个库保留最近几份，默认 8 |
| `--databases` | 指定库名，默认取 `.env` 的 `DB_NAME` / `DB_NAME_DATA` |
| `--mysqldump` | mysqldump 路径，默认自动找 |

退出码 0 成功，非 0 失败。配置了但不存在的库按"跳过"处理，不算失败 —— 本地和服务器的库不一定一样（比如 `traveldata` 只在服务器有）。

## 部署时自动备份（`server_update.sh` 已内置）

`server_update.sh` 的 `[5/6]` 步会**自动执行所有新的迁移脚本** —— 这是数据被改坏最常见的来源。
所以 `[4.5]` 步在跑迁移之前先备份一次，存到 **`backups/db_predeploy/`**（保留 10 份）。

万一某个迁移写错了，这份 30 秒前的快照就是唯一的退路。

- **备份失败会中止部署**：下一步就要动数据库，没有备份等于没有退路
- 确知本次没有迁移脚本、又急着发布，可以 `./server_update.sh --skip-backup` 跳过
- 存独立目录是刻意的：一天可能部署好几次，和每周备份共用目录的话，
  轮转会把每周备份全挤掉

## 设置每周自动执行

### 服务器：`server_update.sh` 会自动装 cron

`[6.1]` 步会检查每周备份的定时任务是否在位，不在就装上（幂等，已有则跳过，
也不会覆盖你其他的定时任务）。所以**部署一次就自动配好了**，不用手动敲。

放进部署脚本而不是让人手动配，是为了换服务器、重装系统后不会忘 ——
忘了也不会报错，等到要恢复时才发现根本没备份。

装的是这条：

```cron
0 3 * * 0 cd /var/www/MyTravelPanel && venv/bin/python scripts/tools/db_backup.py >> logs/db_backup.log 2>&1
```

确认已生效：

```bash
crontab -l
tail -20 /var/www/MyTravelPanel/logs/db_backup.log
```

手动装（不想跑整个部署脚本时）：

```bash
(crontab -l 2>/dev/null; echo "0 3 * * 0 cd /var/www/MyTravelPanel && venv/bin/python scripts/tools/db_backup.py >> logs/db_backup.log 2>&1") | crontab -
```

改时间或删除：

```bash
crontab -l | grep -v 'db_backup.py' | crontab -    # 删掉后再按新时间重装
```

> 不用应用内的 APScheduler：gunicorn 起了 3 个 worker，进程内调度会**同一个任务跑 3 遍**；而且应用挂掉时备份也跟着停 —— 恰恰是最需要备份的时候。

### 本机（Windows 任务计划程序）

以管理员打开 PowerShell：

```powershell
$py  = "E:\MyProject\MyTravelWork\MyTravelPanel\.venv\Scripts\python.exe"
$dir = "E:\MyProject\MyTravelWork\MyTravelPanel"

$action  = New-ScheduledTaskAction -Execute $py `
    -Argument "scripts\tools\db_backup.py" -WorkingDirectory $dir
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Sunday -At 3am
# 到点时机器没开就在下次开机后补跑，否则关机那周就漏了
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable `
    -DontStopIfGoingOnBatteries -AllowStartIfOnBatteries

Register-ScheduledTask -TaskName "MyTravelPanel数据库备份" `
    -Action $action -Trigger $trigger -Settings $settings -Description "每周备份本地 MySQL"
```

立即试跑一次，确认配置没问题：

```powershell
Start-ScheduledTask -TaskName "MyTravelPanel数据库备份"
Get-ScheduledTaskInfo -TaskName "MyTravelPanel数据库备份"   # LastTaskResult 为 0 即成功
```

## 恢复

**恢复是覆盖式的。动手前先把当前库另存一份**，并且强烈建议先恢复到临时库核对无误再动正式库。

```bash
# 1) 先恢复到临时库验证
mysql -u root -p -e "CREATE DATABASE restore_test CHARACTER SET utf8mb4"
gunzip -c backups/db/travelindustry_20260903_030000.sql.gz | mysql -u root -p restore_test

# 2) 核对表数和关键表行数
mysql -u root -p -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='restore_test'"
mysql -u root -p -e "SELECT COUNT(*) FROM restore_test.project_headers"

# 3) 确认无误后再覆盖正式库
gunzip -c backups/db/travelindustry_20260903_030000.sql.gz | mysql -u root -p travelindustry
mysql -u root -p -e "DROP DATABASE restore_test"
```

Windows 上 `mysql.exe` / `mysqldump.exe` 在 `C:\Program Files\MySQL\MySQL Workbench 8.0\` 目录里（装 Workbench 时自带），不在 PATH。也可以直接用 Workbench 的 **Data Import** 图形界面导入解压后的 `.sql`。

## 第二步：把服务器备份取回本机（异地副本）

脚本：`scripts/tools/db_backup_pull.py`

就地备份防不了整台机器丢失。这一步把服务器的备份拉回本机，存到
`backups/db_server/` —— **和本机自己的备份 `backups/db/` 分开放**，
混在一起出事时分不清哪份是哪台机器的，很容易恢复错。

只下载本机还没有的文件（增量），下载后校验完整性，坏的直接丢弃并计为失败。

### 一次性：配置 SSH 免密登录

密码登录没法自动化，必须用密钥。本机 PowerShell 或 Git Bash：

```bash
# 1) 生成密钥（一路回车，密码留空——加了密码就没法无人值守）
ssh-keygen -t ed25519 -C "mytravelpanel-backup"

# 2) 把公钥装到服务器（会要求输一次服务器密码）
ssh root@47.84.177.3 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys" < ~/.ssh/id_ed25519.pub

# 3) 验证免密生效——应该直接进去，不再问密码
ssh root@47.84.177.3 "echo 免密登录成功"
```

### 手动拉一次

```bash
python scripts/tools/db_backup_pull.py --host 47.84.177.3
```

| 参数 | 说明 |
|---|---|
| `--host` | 服务器地址（必填，或环境变量 `BACKUP_SSH_HOST`）|
| `--user` | SSH 用户，默认 `root` |
| `--port` | SSH 端口，默认 22 |
| `--remote-dir` | 服务器备份目录，默认 `/var/www/MyTravelPanel/backups/db` |
| `--dir` | 本机存放目录，默认 `<项目根>/backups/db_server` |
| `--keep` | 本机保留最近几份，默认 8 |
| `--identity` | SSH 私钥路径，默认用 ssh 的默认查找 |

脚本用 `BatchMode=yes`：没配免密时**立刻报错退出**，不会挂在密码提示上把定时任务卡死。

### 每周自动拉取（Windows 任务计划程序）

排在服务器备份之后跑（服务器周日 3:00，本机周日 4:00 拉）：

```powershell
$py  = "E:\MyProject\MyTravelWork\MyTravelPanel\.venv\Scripts\python.exe"
$dir = "E:\MyProject\MyTravelWork\MyTravelPanel"

$action  = New-ScheduledTaskAction -Execute $py `
    -Argument "scripts\tools\db_backup_pull.py --host 47.84.177.3" -WorkingDirectory $dir
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Sunday -At 4am
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable `
    -DontStopIfGoingOnBatteries -AllowStartIfOnBatteries

Register-ScheduledTask -TaskName "MyTravelPanel取回服务器备份" `
    -Action $action -Trigger $trigger -Settings $settings -Description "每周取回服务器数据库备份"
```

试跑并确认：

```powershell
Start-ScheduledTask -TaskName "MyTravelPanel取回服务器备份"
Get-ScheduledTaskInfo -TaskName "MyTravelPanel取回服务器备份"   # LastTaskResult 为 0 即成功
```

> 本机关机那周会漏拉，但服务器上那份还在（保留 8 份），下次开机 `-StartWhenAvailable` 会补跑，把缺的一次性补齐。

## 三个目录分别是什么

| 目录 | 内容 | 谁写的 |
|---|---|---|
| `backups/db/` | 本机 MySQL 的备份 | 本机 `db_backup.py` |
| `backups/db_server/` | 从服务器取回的备份 | 本机 `db_backup_pull.py` |
| 服务器 `backups/db/` | 服务器 MySQL 的每周备份 | 服务器 cron |
| 服务器 `backups/db_predeploy/` | 每次部署跑迁移前的快照 | `server_update.sh` |

**恢复时先看清楚用的是哪一份。** 拿本机的 dump 去覆盖线上库，等于把线上数据换成你本地的测试数据。

## 这套方案防得了什么、防不了什么

**防得了**：改错迁移脚本、跑错 UPDATE / DELETE、误删表、代码 bug 写坏数据；整台服务器丢失（本机有异地副本）。

**防不了**：本机和服务器同时出事；以及**你一周内犯的错，下次备份前还没发现**（每周一次意味着最多丢一周数据）。数据变动频繁的话把频率调高，比如改成每天：cron 写 `0 3 * * *`，`--keep` 相应调大。
