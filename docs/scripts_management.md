# Scripts 文件夹管理说明

## 概述

`scripts/` 文件夹用于存放项目的测试文件、调试脚本、数据检查脚本等临时性文件。这些文件通常包含：

- 测试脚本 (`test_*.py`)
- 调试脚本 (`debug_*.py`)
- 数据检查脚本 (`check_*.py`)
- 迁移脚本 (`migrate_*.py`)
- 临时HTML测试文件

## Git 忽略规则

### 为什么忽略 scripts 文件夹？

1. **临时性质**: 这些文件主要用于开发和调试，不是项目的核心代码
2. **个人化**: 不同开发者可能有不同的测试需求
3. **安全性**: 避免意外提交包含敏感信息的测试文件
4. **仓库清洁**: 保持Git仓库的整洁，只包含必要的生产代码

### .gitignore 配置

```gitignore
# Test and debug scripts
scripts/
```

## 文件管理策略

### 1. 本地开发
- 所有测试文件都放在 `scripts/` 目录中
- 可以自由创建、修改、删除测试文件
- 不会影响Git版本控制

### 2. 团队协作
- 如果需要共享特定的测试脚本，可以：
  - 将文件重命名为 `shared_*.py`
  - 移动到 `docs/examples/` 目录
  - 在项目文档中说明使用方法

### 3. 重要脚本的处理
如果某个测试脚本对团队有价值，应该：

1. **重命名**: 使用 `shared_` 前缀
2. **移动**: 放到 `docs/examples/` 目录
3. **文档化**: 在 `docs/` 中添加使用说明
4. **版本控制**: 手动添加到Git

## 最佳实践

### 1. 文件命名规范
```
scripts/
├── test_*.py          # 功能测试
├── debug_*.py         # 调试脚本
├── check_*.py         # 数据检查
├── migrate_*.py       # 数据迁移
└── shared_*.py        # 共享脚本（可选）
```

### 2. 定期清理
- 删除过时的测试文件
- 整理重复的调试脚本
- 归档重要的测试结果

### 3. 文档记录
- 在 `docs/` 中记录重要的测试方法
- 维护测试用例的说明文档
- 记录常见问题的调试步骤

## 注意事项

### 1. 不要提交敏感信息
- 避免在测试文件中包含数据库密码
- 不要包含API密钥或访问令牌
- 使用环境变量或配置文件

### 2. 备份重要脚本
- 重要的调试脚本应该备份到其他位置
- 考虑使用云存储或代码片段管理工具

### 3. 团队沟通
- 告知团队成员 scripts 文件夹被忽略
- 建立脚本共享的流程
- 定期同步重要的测试方法

## 恢复被忽略的文件

如果需要将某个脚本文件添加到版本控制：

```bash
# 强制添加特定文件
git add -f scripts/important_script.py

# 或者临时取消忽略
git add --ignore-errors scripts/
```

## 总结

通过将 `scripts/` 文件夹添加到 `.gitignore`，我们实现了：

- ✅ 保持Git仓库的整洁
- ✅ 避免意外提交临时文件
- ✅ 提高开发效率
- ✅ 保护敏感信息
- ✅ 支持个人化的测试需求

这种管理方式既保证了项目的规范性，又为开发者提供了灵活的工作空间。
